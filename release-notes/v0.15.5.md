# Nokcandu 0.15.5

## Controllers panel

- **Profiles → Controllers** lists every controller connected now and the ones Nokcandu remembers. Each card shows the controller's own outline, lights up the buttons you press and names them ("A", "ZR", "Left stick"), has **Ping** (a soft buzz) to find it, and says what it's doing: its player and the profile it gets, with the reason ("Noita's choice for this controller", "used everywhere"). Controllers can be renamed.
- **Player**: Auto (the next free player, in the order they connect) or Player 1–8. Several controllers on one player drive it together. Windows games in Nokcandu use these numbers instead of the order Wine opens controllers, and say back which player each became. Streams make the controller set to Player 1 the profile's controller. On the Mac, everything not set to another player drives player 1, and controllers set to player 2 and up are left to Mac games as they are (not taken from macOS, not mapped).
- **Own profile**: a controller's profile in apps and games with no profile of their own choosing (it replaces "With <controller>" in Controller on the Mac; those choices carry over).
- **Per controller** in a game's Controller Profile: a controller given a profile there uses it in that game instead of the game's profile. Pressing a button on another controller switches to that controller's profile.
- The order profiles are chosen in is fixed and shown in the panel: a profile used everywhere; in a game, the game's choice for this controller, then the game's profile; elsewhere, the app's rule, the controller's own profile, then the Mac's.

## Remapping

- **Local co-op**: each controller is its own player, in the order they connect, and players 2 to 4 can each get their controller as it is (its own type, no profile), the same profile, or a profile of their own (the profile's Local co-op section). Windows games in Nokcandu use it now. **Changed**: other players used to get player 1's profile; they now get their controller as it is unless the profile says otherwise. Under Auto, the Steam Controller a profile reads directly is player 1 in Windows games, whichever controller Wine noticed first. Streams already send other players as they are; Mac apps get separate players with the Mac virtual controller.
- **A layer can route differently from the profile**: select a layer and set its routing (Standard, Only what this profile maps, Mappings and the controller itself, The controller itself). One button can now switch the game's own controller controls on and off: for example the base layer sends only your keys and mouse, and a layer you hold or toggle hands the game the controller itself. Buttons that change layers keep doing that in every layer. Windows games and streams switch instantly; Mac apps and CrossOver games get the controller back from Nokcandu while such a layer is on (instant too once the Mac virtual controller is allowed). If Steam Input reads the same controller, Steam games don't get it back from Nokcandu; Controller Settings says so and what to turn off.
- **No double input in Mac games and CrossOver**: while a Mac app is in front with a profile that sends only its own mappings (Routing: Only what this profile maps), or that presents an emulated controller, Nokcandu takes a DualShock 4, DualSense, Xbox Wireless (Bluetooth) or Switch Pro controller from macOS and reads it itself, so the game sees only the profile's keys and mouse, not the controller as well. Game rumble, gyro and the profile's rumble keep working. The controller is macOS's again as soon as the profile stops applying. Turn it off in Controller Settings → "Hide other controllers from Mac games while a profile maps them".
- **Anti-deadzone**: a stick that moves a stick can start past the game's own dead zone (the stick's settings → Game's dead zone), so fine aim isn't swallowed.
- **Game rumble defaults to 7% on the original Steam Controller** (its trackpad haptics are harsh at full strength) and to 100% on every other controller, the 2026 Steam Controller included. A profile's own setting is kept.
- **Fixed**: gyro from controllers Nokcandu reads itself (taken-over controllers, Switch 2 controllers, 8BitDo, GameSir and other report-read controllers) turned as roll instead of yaw: their motion reached the profile in the wrong axes.
- **Fixed**: with the 2026 controller's labels, the original Steam Controller's right trackpad click ran the right stick click's mapping.
- **Fixed**: a game inside Steam or another shared launcher with a controller profile or keyboard layout of its own didn't get it (its controller kept working as it is, and only a profile used everywhere reached it): the game was looked up by the wrong one of its program's arguments.
- **Fixed**: with a profile that reads the original Steam Controller directly, Windows games got no Steam Controller at all while Nokcandu read it exclusively (Controller Settings, on by default): Nokcandu's controller driver now puts a stand-in for it in the game, presented as the profile says.
- **Fixed**: a profile used everywhere that presents the controller as Xbox, DualShock 4 or Switch Pro didn't in Windows games; only a game's own profile did.
- **Fixed**: players 2 and up left "as it is" in a profile's Local co-op were still presented as the profile's emulated controller.
- **Fixed**: in a Windows game with two or more controllers, player 2's presses also typed player 1's keyboard and mouse mappings (once the game reports its players).

## Controller overlay

- **With several controllers, the overlay shows player 1's** (Controller overlay → With several controllers), so other players' presses no longer flip it back and forth. Player 1 is what a running Windows game reports, else the Controllers panel's Player, else the Auto order. "The controller used last" keeps the old behaviour.

## Stability and safety

- **Accessibility quick setups** (Quick Setup → Accessibility): every hold becomes a toggle (press once to hold, again to let go), and one-handed layouts: hold L for the right side's controls on the left (D-pad as the face buttons, left stick as the right stick, ZL/LT as RT), or hold R for the left side's on the right.
- **Updates across the move to Developer ID**: a build that names Nokcandu's Apple Developer team accepts updates signed with that team's Developer ID and notarized by Apple, so the first Developer ID release can update it in place and later ones survive certificate renewals.
- **Gyro calibration holds**: a slow, steady flat turn (panning the camera) is no longer mistaken for drift and learned as the new resting reading; a large correction now needs ten quiet seconds that agree. A Switch Pro taken over from macOS applies its own stored motion calibration, as macOS does, so taking it over or handing it back no longer shifts the gyro.
- **No keys left stuck after a crash**: Nokcandu keeps track of what it's holding down, and the next launch lets go of anything the last run left held. Waking the Mac lets go of anything still held from before sleep.
- **Crash notice**: if Nokcandu quit unexpectedly, the next launch says so in Recent Activity (the bell) and where macOS kept the report.
- **Shared profiles say what they do**: before adding a profile from a link or file, Nokcandu lists any text its macros type and any ⌘ shortcuts it presses, and asks you to add only profiles you trust.
- A Steam Input layout or a game's install script nested thousands of levels deep could crash Nokcandu; it's now refused. Found by new tests that throw random data at everything Nokcandu reads from outside.
- **Fixed**: choosing a game's Graphics mode, Vulkan layer, Mac screen resolution or window style could show the old choice again after saving.

## Controller overlay and profile editor

- **Rumble** has its own button under Gyro in the profile picture (it was the Feedback link under it).
- The 2026 Steam Controller's Gyro button sits between the handles, like the other controllers'.
- A mapped button's caption no longer pushes the button out of place, and the Nintendo − and + captions sit above their buttons.
- The Switch Pro overlay's D-pad is full size; the editor's picture keeps one D-pad size for every controller.
- **Fixed**: the Switch Pro overlay showed A, B, X and Y by position, so A and B, and X and Y, lit up swapped.

## Streams

- **End App** is one name everywhere for closing the app running on the host (the stream ends with it): the stream page's button, the host's menu, the Stream menu, the menu bar and the toolbar's running stream. It was Quit App on Host, End and Quit App, and End Stream and Quit the App on the Host.

- **Stream health verdict**: the statistics graphs say in plain words where the last minute's hitches came from: the network (with how late and how often), this Mac's decoding, or the host's encoding, or that it was smooth.
