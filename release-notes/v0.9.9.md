Saved and shared profiles now include BF1942 display settings and once-per-frame mouse delivery, with compatibility checks and file-level Undo. Existing profiles remain supported.

Game pages show estimated storage with drive names and split-location details. Moves preserve renderer paths and private fix history, and ExFAT handling uses the appropriate files-only path and reliable free-space reporting.

The Steam-closed note now sits with Mac screen resolution. Borderless display uses the standard Fullscreen (Borderless) label.

Raw Mouse Capture is now off by default for new game environments. Existing choices are preserved. Its help text correctly describes live switching, and BF1942 shows a compatibility note.

Adds an optional “Hide stray Mac pointer” fix for a system arrow remaining visible during gameplay. It follows Wine cursor visibility and leaves raw input off. Includes profile sharing and Undo.

Fullscreen (Borderless) now refreshes stale native mouse-confinement bounds after a window resize, addressing restricted menu and camera movement that previously recovered after Cmd-Tab.

Disc installation and generated launchers use the current read-only disk-image mounting command on macOS 27, with the legacy path retained for earlier macOS versions.

Disc copying/conversion shows measured progress and supports cancellation with partial-file cleanup. Mount cancellation terminates the active command; permanent failures are not retried repeatedly. The CD-music warning now explains data-only ISO import and why LAV is not applicable.

The experimental stray-pointer fix is unavailable for BF1942 following reports of cursor flicker. Its separate borderless mouse-bounds correction remains available.

- Game-folder installs now find executables through C: links to external drives, fixing successful copies reported as failures (including OpenUA). Cyclic links are bounded; retries never erase a populated destination.
- Added Use Existing Folder Without Copying for folder installs. Borrowed files are kept on removal. Disc setups can import a manually selected game folder after setup when legacy installers leave no executable behind.
- Removal now lists dedicated external game files in its confirmation, excludes borrowed/shared folders, and retains remaining records if removal fails. Removing unfinished setups ejects their discs first and keeps setup progress if the app cannot be trashed.
- Game-file copies strip verified AppleDouble metadata sidecars while preserving source files and ordinary dot-prefixed game files. This prevents engines such as OpenUA from treating Mac metadata as level data and crashing during startup.
- OpenUA now has a game-specific recommended display fix with safe Undo. Saved/shared profiles capture the recipe, including already configured manual installations. Its controls stay hidden for other games.
- Fixed compatibility controls incorrectly asking for a program on C: when the selected executable is in a linked game folder on an external drive. Links that escape the game folder remain rejected.
- Fixed a shared launcher regression that could prevent Zero Hour and native helper tools from starting: the Intel mouse/Dock helper is now passed only to Wine, rather than exported to native Python and other utilities. The correction covers built-in recipes, general game launchers and shared Steam. Recognised existing launchers upgrade on maintenance or before launch/check; user-edited launchers are kept.
