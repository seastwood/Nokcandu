# Nokcandu 0.15.4

## Import Steam Input layouts

- **New Controller Profile → Import Steam Input Layout…** turns a Steam Input layout (a game's from Steam Controller Configs, or a community layout) into a Nokcandu profile: buttons, bumpers, back grips, D-pad, triggers (soft and full pull), joysticks (stick, mouse, flick stick, scrolling, directions, click, outer ring), trackpads (mouse, mouse-like stick, stick, directions, scroll wheel, mouse region; radial and touch menus become trackpad buttons), the gyro, and each button's press, long press, double press, release and toggle. Action layers become layers with their names, and mode shifts become layers held while their button is. Anything that works differently here or couldn't come across is listed afterwards.

## Controllers panel

- **Profiles → Controllers** lists every controller connected now and the ones Nokcandu remembers. Each row shows the buttons you're pressing as you press them ("A", "ZR", "Left stick") and lights up, has **Ping** (a soft buzz) to find it, and says what it's doing: its player and the profile it gets, with the reason ("Noita's choice for this controller", "used everywhere"). Controllers can be renamed.
- **Player**: Auto (the next free player, in the order they connect) or Player 1–8. Several controllers on one player drive it together. Windows games in Nokcandu use these numbers instead of the order Wine opens controllers, and say back which player each became. Streams make the controller set to Player 1 the profile's controller. On the Mac, everything not set to another player drives player 1, and controllers set to player 2 and up are left to Mac games as they are (not taken from macOS, not mapped).
- **Own profile**: a controller's profile in apps and games with no profile of their own choosing (it replaces "With <controller>" in Controller on the Mac; those choices carry over).
- **Per controller** in a game's Controller Profile: a controller given a profile there uses it in that game instead of the game's profile. Pressing a button on another controller switches to that controller's profile.
- The order profiles are chosen in is fixed and shown in the panel: a profile used everywhere; in a game, the game's choice for this controller, then the game's profile; elsewhere, the app's rule, the controller's own profile, then the Mac's.
- **Fixed**: in a Windows game with two or more controllers, player 2's presses also typed player 1's keyboard and mouse mappings (once the game reports its players).
- **Fixed**: a profile used everywhere that presents the controller as Xbox, DualShock 4 or Switch Pro didn't in Windows games; only a game's own profile did.
- **Fixed**: players 2 and up left "as it is" in a profile's Local co-op were still presented as the profile's emulated controller.
- Under Auto, the Steam Controller a profile reads directly is player 1 in Windows games, whichever controller Wine noticed first.
- **Fixed**: choosing a game's Graphics mode, Vulkan layer, Mac screen resolution or window style could show the old choice again after saving.

## Profiles

- **Copy Link** (Share): a nokcandu:// link that carries the whole profile, with what it builds on, its macros, menus and layers. Opening it on a Mac with Nokcandu asks before adding it; nothing is uploaded.
- **Profiles for Mac Apps** (Settings → Controller on the Mac) is always shown: any Mac app can have its own profile, or Off, whether or not a profile is used on the Mac otherwise. App icons, "Add a Running App", and the profile list names the apps that use each profile.
- The profile list shows each profile's controller as a small outline (its pads, touchpad or sticks), or a generic controller when none is chosen.
- **Rumble when the gyro turns on or off**: one pulse on, two off.

## Remapping

- **Local co-op**: each controller is its own player, in the order they connect, and players 2 to 4 can each get their controller as it is (its own type, no profile), the same profile, or a profile of their own (the profile's Local co-op section). Windows games in Nokcandu use it now. **Changed**: other players used to get player 1's profile; they now get their controller as it is unless the profile says otherwise. Streams already send other players as they are; Mac apps get separate players with the Mac virtual controller.
- **A layer can route differently from the profile**: select a layer and set its routing (Standard, Only what this profile maps, Mappings and the controller itself, The controller itself). One button can now switch the game's own controller controls on and off: for example the base layer sends only your keys and mouse, and a layer you hold or toggle hands the game the controller itself. Buttons that change layers keep doing that in every layer. Windows games and streams switch instantly; Mac apps and CrossOver games get the controller back from Nokcandu while such a layer is on (instant too once the Mac virtual controller is allowed).
  If Steam Input reads the same controller, Steam games don't get it back from Nokcandu; Controller Settings says so and what to turn off.

- **No double input in Mac games and CrossOver**: while a Mac app is in front with a profile that sends only its own mappings (Routing: Only what this profile maps), or that presents an emulated controller, Nokcandu now takes a DualShock 4, DualSense, Xbox Wireless (Bluetooth) or Switch Pro controller from macOS and reads it itself, so the game sees only the profile's keys and mouse, not the controller as well. Game rumble, gyro and the profile's rumble keep working. The controller is macOS's again as soon as the profile stops applying. Turn it off in Controller Settings → "Hide other controllers from Mac games while a profile maps them".
- Gyro from controllers Nokcandu reads itself (taken-over controllers, Switch 2 controllers, 8BitDo, GameSir and other report-read controllers) turned as yaw instead of rolling: their motion reached the profile in the wrong axes.
- **Anti-deadzone**: a stick that moves a stick can start past the game's own dead zone (the stick's settings → Game's dead zone), so fine aim isn't swallowed.
- **Game rumble defaults to 7% on the original Steam Controller** (its trackpad haptics are harsh at full strength) and to 100% on every other controller, the 2026 Steam Controller included. A profile's own setting is kept.
- With the 2026 controller's labels, the original Steam Controller's right trackpad click runs the right trackpad click mapping (it ran the right stick click's).

- **Outer ring** on sticks: something extra while the stick is pushed near its edge, on top of what it does (walk, and hold Shift to run at the edge). Set how far out it counts.
- **When let go**: an action as a button is released, whatever it did while held (throw on release). A button can keep doing what it's called and have one.
- **Cycle**: each press does the next in a list of up to four (weapons 1, 2, 3; zoom levels).
- **Long hold**: held longer still, a third action takes over from the hold (reload, then inspect), with its own time.
- **Tap fires at once**: the tap happens the moment you press instead of after it's clear it wasn't a hold or double tap; a hold or double tap still follows.
- **Scroll left / right** as outputs.
- **Trackpad as buttons**: a new pad behavior, "Buttons (zones you set)", where the pad is only buttons. The one under your thumb is held while it's there (slide to change), and clicking presses its click. Layouts: halves, corners, centre and four sides, and new radial layouts of four, six and eight slices with a free middle. Each button can be set to anything.

## Stability and safety

- **Accessibility quick setups** (Quick Setup → Accessibility): every hold becomes a toggle (press once to hold, again to let go), and one-handed layouts: hold L for the right side's controls on the left (D-pad as the face buttons, left stick as the right stick, ZL/LT as RT), or hold R for the left side's on the right.
- **Updates across the move to Developer ID**: a build that names Nokcandu's Apple Developer team accepts updates signed with that team's Developer ID and notarized by Apple, so the first Developer ID release can update it in place and later ones survive certificate renewals.

- **Gyro calibration holds**: a slow, steady flat turn (panning the camera) is no longer mistaken for drift and learned as the new resting reading; a large correction now needs ten quiet seconds that agree. A Switch Pro taken over from macOS applies its own stored motion calibration, as macOS does, so taking it over or handing it back no longer shifts the gyro.
- **No keys left stuck after a crash**: Nokcandu keeps track of what it's holding down, and the next launch lets go of anything the last run left held. Waking the Mac lets go of anything still held from before sleep.
- **Crash notice**: if Nokcandu quit unexpectedly, the next launch says so in Recent Activity (the bell) and where macOS kept the report.
- **Shared profiles say what they do**: before adding a profile from a link or file, Nokcandu lists any text its macros type and any ⌘ shortcuts it presses, and asks you to add only profiles you trust.
- A Steam Input layout or a game's install script nested thousands of levels deep could crash Nokcandu; it's now refused. Found by new tests that throw random data at everything Nokcandu reads from outside.

## Controller overlay and profile editor

- **Rumble** has its own button under Gyro in the profile picture (it was the Feedback link under it).
- The 2026 Steam Controller's Gyro button sits between the handles, like the other controllers'.
- The Switch Pro overlay's D-pad is full size.
- The Switch Pro overlay shows A, B, X and Y where they are on the controller (they showed by position, so A and B, and X and Y, lit up swapped).

- **The Xbox, Switch Pro and DualSense look like themselves**, in the overlay and the profile editor: their outlines traced as plain shapes, with every stick, button, D-pad and touchpad where it is on the controller. Labels beside the small buttons are placed to match.
- PlayStation face buttons show as ✕ ○ □ △, with Create, Options and Mute in words.
- D-pad mappings in the editor sit outside the D-pad, so neighbours never overlap.

- A trigger's full pull shows on the trigger (⇊ and what it does), and the trigger is ringed when its full pull is toggled on.
- The profile editor's picture of the Steam Controller (2015) has its real outline and centre panel, with every part where it is on the controller; Back's and Start's mappings show above them.

## Headphone motion

- Head motion takes its centre once your head has been still for a moment after starting or putting the earbuds in (it used to start pointed wherever your head was, often down, and could press that direction).

## Streams

- **Stream health verdict**: the statistics graphs say in plain words where the last minute's hitches came from: the network (with how late and how often), this Mac's decoding, or the host's encoding, or that it was smooth.

- **Layer, gyro and calibration notes show in full-screen streams**, drawn into the stream's picture like the overlay and statistics: no window over the stream, so no added delay. They show even with "Hold notifications while playing" on, since they no longer slow the stream down.
- **With the display layer**, the Streams page now warns when anything would be drawn over the picture (statistics and graphs, the controller overlay, the head-motion picture, layer and gyro notes) and offers **Use Metal**: over a full-screen stream those make macOS combine the screen every frame, which adds delay. The stream's log notes it too.
