# Storage inventory: game files outside app bundles — 2026-11-03

## Confirmed cause and shared correction

The Storage Games inventory used an older app-size-plus-selected-folder calculation. It did not reuse the broader game-detail accounting, so Steam/Battle.net/EA/Ubisoft shortcuts could show only a tiny Mac launcher even when their game files were on another drive. Private games launched through a separate hub had another gap: changing the selected program could hide the original linked game directory from both inventory and game-detail totals. The earlier Storage browsing performance improvement did not fix this location/accounting mismatch.

The Games inventory now uses the shared game-usage calculation. Rows include the app, registered launcher game installation root, known native install folder and separately linked private game content, with sizes and drive names in the detail. Launcher rows exclude game directories listed separately, rather than presenting the same internal game bytes under both the shared host and the game row. Launcher-detail summaries can still include their installed games across drives. Canonical duplicate/nested game locations are counted once within a usage result. APFS allocated-block estimates remain estimates; this does not establish unique deletion savings or a grand total across all rows sharing files.

Private content discovery is bounded to explicit directory links in the game's private C: game containers and one publisher subdirectory level. It does not walk users/, dosdevices/, drive roots or arbitrary directory links elsewhere in the app. This covers a hub/client selected outside the actual game directory without a game-specific override. The directory walks that measure app contents still do not follow arbitrary symlinks. Native known install roots containing their app are counted once; an app outside its native game-data root is included separately.

Unavailable files or lost launcher metadata produce an incomplete estimate, labeled “At least,” with unavailable game files identified. They are not claimed to be a complete tiny-app total. File moves invalidate the shared inventory; library revision changes re-request displayed Storage/folder results, preserving the existing on-demand cache for unrelated refreshes.

## Verification and safety

270 tests passed, with ten optional skips and zero failures. New regressions cover split private games, EA and Ubisoft mapped drives, Battle.net installation roots, Steam external library manifests and missing metadata, internal shared-host separation, native install data, hub-selected private games, duplicate aliases and user-folder exclusion. The Steam fixture writes only explicit temporary fixture paths and verifies its environment override before invoking the read-only global lookup; it never moves or modifies the user's Steam host. Automatic review rejected an earlier test proposal that used the global host URL as a mutation destination. That proposal did not run and was replaced by explicit fixture-local paths.

No game files, drive mappings, settings, saves, profiles or launchers are changed by this accounting correction. Existing and new installations use the same resolver automatically. A normal app restart discards older session estimates; Refresh forces remeasurement. Undo is returning to the previous app build, which restores the previous display/calculation without changing game data. UI verification is recorded after inspecting the built update.

## Direct UI confirmation and installation

The built app was opened before installation and measured the existing library without modifying game files. The Games inventory showed CS2 as 76.86 GB with game files on Elements, replacing its former 197 KB shortcut-only figure. BF2 showed 9.09 GB total: 3.05 GB app on Macintosh HD plus 6.04 GB content on Elements. BF1942 showed 1.94 GB app plus 4.82 GB content on Elements, and BC2 showed 369 KB app plus 11.06 GB content on Elements. Counter-Strike: Source showed its 5.87 GB installation on Macintosh HD. Search remained responsive during measurement and returning filtered rows used the completed result. These directly confirm both external and internal shared-launcher content and hub-selected private content. The signed update was installed with a verified rollback copy; no game files were moved or removed.
