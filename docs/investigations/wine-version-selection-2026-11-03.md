# Explicit Sikarugir Wine versions — 2026-11-03

## Scope and design

Previously Updates offered the newest Wine engine and a Keep/Roll Back trial. The user requested a version dropdown per game, a default for new installations and an installation override, beginning at Wine 10.0. The [official Sikarugir release catalog](https://github.com/Sikarugir-App/Engines/releases/tag/v1.0) was checked: the v1.0 release contains Wine 10.0, revisions 1–8, and Wine 11.0/revision 1 with published checksums. Nokcandu's original tested engine is specifically **Wine 10.0 r8**, not revision zero; the initial default remains that exact tested build. Older Wine families, unrelated engine distributions, specialty unchecksummed builds and versions below 10.0 are excluded.

`WineSelection` centralizes version parsing, choices, install defaults, immutable saved choices, Sikarugir runtime preparation and host resolution. The selector uses the verified original Sikarugir 1.0.24 wrapper/graphics template while varying Wine; it does not mix arbitrary Wine distributions or auto-select a newer wrapper. Other compatible verified engine/template combinations already installed through Updates remain intact. Downloaded engines require the existing published checksum and scratch Windows startup self-test. Known failed combinations cannot be selected. This checks basic Windows execution, not every game's compatibility.

## User controls

- Game pages expose Wine version and Use Selected Wine, plus the current version and existing Keep/Roll Back trial. Explicit selection can change a held engine; the hold itself remains intact, so future update suggestions still respect it. A pending trial must be kept or rolled back before replacing its recovery copy.
- Settings → General → New games stores a concrete default, initially Wine 10.0 r8. It never means automatically follow latest, and changes no existing app.
- Add a Game exposes an optional per-install choice. New installer state snapshots the selected/default engine. A retained store/client setup now shows the choice before its first Continue. Once runtime preparation begins, the choice cannot change mid-prefix; later changes use the normal game setting. Saved/resumed installs retain their snapshot. Legacy unfinished states without the new field continue with the original Wine 10.0 r8.

Steam, Battle.net and hosted store games use the Wine engine of their actual shared host. The game page explicitly states the affected scope; it does not pretend that a small shortcut can use a separate Wine engine inside a running shared Windows environment. Changing it uses the existing full-environment restart confirmation. Native games have no Wine selector. Version-dependent features remain guarded: Native IPX requires the supported Wine 11.0 family; resizable-window limitations are shown before a switch.

## Installation, migration, Repair and Undo

The shared runtime and app-creation stages install the chosen runtime before wineboot, across recipe, general/store and new shared Steam setups. A nonbaseline fresh install records its exact cached runtime as kept provenance, so Repair and a later engine rollback do not mistake it for the recipe's original engine. If its verified cache is missing, Repair reports that fact and preserves the selection instead of falling back to the recipe engine. The Zero Hour recipe compares builtin D3D files against the selected engine's own verified cache, instead of applying Wine 10 hashes to every Wine version. Existing launcher scripts, game content, saves and explicit game settings are not rewritten merely by changing the default or opening the picker.

Existing games are read in place and retain their engine until the user applies a choice. The existing engine-switch transaction retains the prior runtime and rewritten Windows system/registry parts for exact rollback; applying a choice does not silently discard an unresolved trial. Cache cleanup protects the installation default and saved unfinished-install choices as well as active/previous game runtimes. Profiles continue recording the actual host Wine in their tested configuration; machine-wide installation defaults are not applied through a profile or used to silently switch a shared host.

Undo a default by choosing another default, and undo an unkept game change with Roll Back. After Keep, an older available verified version can still be explicitly selected as a new trial. Reverting the Nokcandu app leaves existing selected runtimes and game data in place. No new persistent system service or permission is introduced.

## Validation record

Ten policy regressions cover the original default, explicit overrides and persistence, legacy resumes, invalid versions, verified historical versions/family filtering, selected-runtime provenance, refusal after runtime preparation, shared-host resolution, Native IPX requirements, cache retention and refusal to substitute the recipe engine when its selected recovery cache is missing. Detailed checks use temporary fixtures and isolated preferences. The first isolated test submission did not execute because automatic approval review was at capacity; the same reviewed action succeeded on retry. This was an approval-service availability failure, not an unsafe-action determination.

The opt-in historical Sikarugir test downloads only the official verified runtime into Nokcandu's cache and changes a disposable clone. It verifies a Windows command, held-engine explicit selection, retained hold and exact engine/registry rollback. The historical test passed: official Wine 10.0 with Sikarugir template 1.0.24 ran a Windows command and a disposable Wine 11.0 r1 game clone switched to it, retained its hold, then restored the engine and registry hashes exactly on rollback. A separate fresh recipe test passed: Wine 10.0 created its private prefix, recorded its selected runtime for Repair, and its builtin D3D files matched the chosen engine. The full suite passed 298 tests with 12 optional skips and zero failures. After the final missing-cache Repair safeguard, all 17 targeted Wine-selection/helper/companion recovery checks passed, including the tenth policy regression that verifies no recipe-engine substitution or mutation of the selected engine. The production build passed. Preview UI verification showed all official Wine 10.0–11.0 r1 revisions in the game menu, the unchanged Wine 10.0 r8 default in General settings, the Default override in Add a Game, and Steam host/trial scope on a CS2 page. No real game engine or installation default was changed during UI verification. The signed update was installed and reopened successfully; its game Wine dropdown and revised update guidance were verified in the installed app. The previous Nokcandu app is retained outside Applications for rollback. No claim of gameplay compatibility for every historical Wine build is made.

## Later upgrade-direction regression

The initial historical-target test did not cover Wine 10 → 11 with an existing Wine 10 identity wrapper. A later Falconeer report reproduced an ntdll lookup failure in that direction; see [stale-wrapper upgrade investigation](wine-upgrade-stale-wrapper-2026-11-03.md) for the shared correction and additional verification.
