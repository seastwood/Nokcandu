# Shared helper activation and repair hardening — 2026-11-02

## Scope and behavior

All managed Wine installations, including private games, recipe installations and shared-client shortcuts, use the central audio/input helper generation and Repair path. Native Mac games do not receive Wine helpers. The BF2 socket correction remains shared, and the user has now confirmed login, server browsing, joining an Internet match and moving around. No router, account, global DNS, firewall or game-specific network override was needed.

Installed and active versions are distinct. The build embeds a source-derived helper ID and ships a companion version marker. The loaded helper writes only PID, kernel birth time, build and server/program role beside the owning host's helper. The wineserver poll and kqueue boundaries also record after daemonization. Status checks compare the current bundled/installed bytes, live process ownership and matching birth time. Missing old-version evidence means restart required, not proof that a repair activated. Stale records cannot validate a reused PID. Linked record directories are not created/followed by the native writer. These records contain no command lines, credentials, packets or recordings.

A failed/empty/overlapping process scan is unknown. The process cache retains its last successful rows, does not hold its lock across the scan, and retries failures at a bounded interval. The UI retains its last known running state, shows unavailable status and does not infer a quit/cloud-save upload from a failed scan. Closed-game mutation guards reject unknown status. Shared microphone privacy metadata likewise retains a possibly active sibling's opt-in capability.

## Repair and migration

Repair atomically verifies/restores the shared helper without changing saved microphone/input policies. With the Windows environment closed it also verifies/restores the screen tool, restores a missing journal-owned native entry, rebuilds generated wrappers and route tables through shared generation, checks their signed loader bytes, repairs owned shared Steam scripts, and checks installed compatibility companions. Unknown launcher scripts and replacement native entries are preserved, including recipe, Steam and Battle.net scripts. Shared Steam script generation records ownership so later missing-script recovery and known-version migration can distinguish external edits. A recipe's unrecognized launcher is now preserved rather than overwritten.

Wrapper source stamps alone cannot detect a damaged loader: generated wrappers now retain a signed-loader checksum outside the signed app. Legacy wrappers are adopted after signature verification; invalid generated wrappers are rebuilt from their selected engine. The normal bundle signature verification is used for wrappers: strict symlink checks reject their intentional links back to the owning Wine engine. A real signed-wrapper test checks this layout and corrupted-loader recovery; an earlier strict-wrapper comparison rejected valid engine links and is not used as a damage signal. The wrapper's signature is not invalidated by writing its checksum after signing.

Small journal-owned compatibility binaries get checksum-addressed local recovery copies at installation and normal library migration. Layered fixes use the latest ownership entry for each path. Missing companions can be restored from a verified copy with the original change journal/Undo intact. External edits and links are preserved and reported. A preexisting missing companion without a verified copy is reported as needing component reinstallation. Game executables, Ubisoft browser patches, settings and saves are excluded; recovery files are local runtime data, never repository content. Optional components are never enabled by Repair. Active shared hosts defer companion rebuilds until closed.

Existing running Windows sessions keep their mapped helper until their normal full environment restart. The app reports this rather than terminating them. Fresh installations receive the same generation paths, current helper and version ID. Saved/shared profiles continue to reference compatibility component IDs and per-game settings; activation records and machine recovery caches are not profile payloads.

## Verification

Automated checks cover failed/overlapping scans, last-good-state retention, PID birth/build mismatches, actual native loaded-record generation, missing/changed native entry preservation, missing/corrupt wrapper loader recovery, screen helper permissions and link refusal, checksum recovery, layered ownership and Undo. The full suite passed 261 tests, including 10 explicitly optional skips, with zero failures. The production app build and strict deep signature verification passed.

CI now runs actual Windows Winsock probes on pinned official Wine 10 and 11, in both 32- and 64-bit programs: graceful response+EOF, refused connection, real urgent data and reset. Each run creates and stops only its disposable prefix and contacts only a synthetic loopback listener. The regression asserts all response bytes, readable clean EOF and continued visibility of genuine errors; it uses no game/account/server traffic. The exact pinned-download matrix passed all 16 engine/architecture/mode combinations, including live wineserver loaded-build evidence. The existing mock boundary tests remain the faster unit layer.

An initial activation check inspected records only after a console probe finished and assumed the server was still alive; short-lived servers make that assumption invalid. Observe the server during execution. That stronger comparison also found Wine 11 can enter its kqueue loop without calling the poll hook, leaving only the pre-daemonization parent record. Record from both event-loop boundaries; do not perform filesystem/dyld work in a fork callback. Socket results remain unchanged by this bookkeeping. Earlier socket-only checks had passed all 16 combinations, but did not establish daemonized activation-record coverage.

## Undo and limits

Restore the prior Nokcandu build and fully close/reopen an affected Windows environment to activate its prior shared helper. Per-fix Undo remains journaled and preserves later external edits. Native-entry Undo retains its existing ownership checks. Recovery caches may be removed without changing game content; their absence limits future missing-file recovery. Removing loaded-version records causes conservative restart-needed status until the next launch records evidence again. No automatic game restart occurs.

Basic BF2 Internet gameplay is user-verified. Extended sessions, every anti-cheat implementation, and every supported game are not established by that result. Missing old helpers that were never snapshotted cannot be reconstructed without a verified source; Repair states that limitation explicitly.
